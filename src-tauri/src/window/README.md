# window(ウィンドウ・ショートカットキー・トレイ)

ランチャーのウィンドウの表示・非表示、グローバルショートカット、タスクトレイ、デスクトップモードを受け持ちます。

## 担当すること

- `visibility.rs`: 表示・非表示・終了・最前面・メモリの節約・角丸の無効化・ブラウザ標準のショートカットの無効化・起動時の「画面の用意ができた」の合図(`app_ready`)。
- `hotkey.rs`: グローバルショートカット(1 段階・2 段階)の解析と登録。
- `tray.rs`: タスクトレイのメニューの項目と、スタートアップ(自動起動)の登録。
- `desktop_mode.rs`: デスクトップモード(常に一番後ろ・最大化して固定・最小化や移動を受け付けない)。
- `events.rs`: ウィンドウのイベント(閉じる・大きさや位置の変更)と、ショートカットのイベント。

## 担当しないこと

- どんな設定にするか(画面の設定パネルと、`config/`)。ここは、設定を、ウィンドウに反映する。
- 画面の中身。

## 設計の理由

- **ウィンドウは、画面の用意ができてから出す**: 起動時は、画面がアイコンの取得を終えて `app_ready` を呼ぶまで出さない(`ready` / `want_show`)。
  用意前にショートカットなどで呼ばれたら、用意できた時に出す(`mark_ready`)。アイコンが途中で入れ替わって見えないように。
- **隠している間は、メモリを減らす**(`set_low_memory`): 隠すとき、WebView2 のメモリの目標を下げ、出すとき、戻す。
  あわせて、設定を書き出し(`flush_config`)、Web ミニアプリのウィンドウも閉じる。**デスクトップモードでは、隠さない**。
- **2 段階のショートカットは、キーフックを使わない**(`hotkey.rs`): 「修飾キー + キー」を押すと、約 1.5 秒だけ 2 つ目のキーを待ち受ける。
  キーボードを常時監視しない代わりに、待ち受け中の 1.5 秒だけ、2 つ目のキーが、ほかのアプリに届かない。
  待ち受けには世代番号を付け、古い待ち受けの自動解除が、新しいものを解除しないようにしている。
- **デスクトップモードは、ウィンドウの手続き(サブクラス)で実現する**(`desktop_subclass_proc`): どの操作でも、重なり順を「一番後ろ」にし、
  最小化・移動・大きさの変更・最大化の切り替えを受け付けない(`Win + D` などで最小化されたあとの復元だけは通す)。モードのあいだだけ働く。
  デスクトップモードにする前に最大化していたかを覚え、切ったときに、その状態へ戻す。**Windows のデスクトップそのものの置き換えではない、疑似的なもの**。
- **ブラウザ標準のショートカット(Alt+←・F5・Ctrl+R など)は、無効にする**(`disable_browser_accelerators`): 残すと、アプリのキー操作が、届く前にブラウザに取られる。
- **二重に起動したら、新しく開かず、いまのウィンドウを前に出す**(`lib.rs` の single-instance)。

## 触るときの注意

- ショートカットの既定は `Ctrl+Alt+L`。以前の既定(`Alt+Space+L`)が設定に入っていたら、起動時に付け替える(`OLD_DEFAULT_HOTKEY`)。
- 実機でしか確かめられない(最前面・デスクトップモード・トレイ・ショートカット)ので、`docs/manual-test.md` を見る。
- テストは `src-tauri/src/tests/window.rs`。
