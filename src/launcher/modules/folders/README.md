# modules/folders(フォルダとアイコンの操作)

登録したフォルダ、そのフォルダを開いた画面、フォルダ・アイコンへの操作(作成・名前の変更・移動・外す・削除)を受け持ちます。

## 担当すること

- **ホームのタイルと、開いた画面**: `FolderTile`(ホームのフォルダ。中のアイコン 9 個を見せる)、`FolderView`(開いたフォルダ)。
- **一覧の取得と並び順**: `useFolderItems`(フォルダの中身。覚えている一覧を先に出す)、`FolderModel`(`applyOrder`: 保存した並び順で並べ、無いものは後ろへ)。
- **操作**: `useFolderActions`(フォルダの追加・作成・名前の変更・一覧から外す、アイコンの追加・削除(ごみ箱へ)・名前の変更・ホームへの落とし込み、新規ファイルの作成、並び順の保存、エクスプローラーなどのシェルの操作)。
- **名前の変更の画面**: `RenameDialog`(フォルダ)、`RenameItemDialog`(ファイル。拡張子は変えられない)、`FolderDialogs`(名前の変更・削除の確認をまとめて出す)。
- **ファイル名の決まり**: `ItemNameModel`(使えない文字・Windows が使う名前・長さの検査、並び順の記録の付け替え)。

## 担当しないこと

- ホームの並び・ホームとフォルダ間のドラッグの受け渡し(`modules/home`)。
- 元に戻す履歴そのもの(`modules/history`)。ここでは、操作のたびに履歴へ積むだけ。
- ファイルの実際の移動・削除・名前の変更(Rust の `files/operations.rs`)。登録フォルダの外は、Rust 側が断る。

## 設計の理由

- **ファイル名の決まりは、画面(`ItemNameModel.checkStem`)と Rust(`check_new_file_name`)の両方に持つ**。
  画面は、入力中に理由を出し、保存を止めるため。Rust は、画面を通らない呼び出しからも守るため。**片方を直したら、もう片方も同じに直す**
  (テストは両方にある: `ItemNameModel.test.ts` と `src-tauri/src/tests/files.rs`)。
- **拡張子は、変えられない**: `.lnk` を `.exe` にするなど、ファイルの種類のすり替えを防ぐため(画面でも Rust でも検査する)。
- **名前を変えたら、並びの記録も付け替える**(`replacePathInOrders`): ホームの記録は `i:<パス>`、フォルダの記録は、パスそのもの。
  大文字・小文字と `/` の違いは、同じものとして扱う(Windows のため)。
- **「ホームの並び」と「フォルダの中の並び」は、同じ `orders` に入る**(キーが違うだけ): ホームは `__home__`、フォルダはフォルダのパス。
- **操作は、元に戻せるようにする**: 変更の前に `snapshot` を撮り、`pushHistory` に、元に戻す処理とやり直す処理を渡す。
  実際のファイルの移動・名前の変更も、元に戻す(戻す側で、もう一度 Rust を呼ぶ)。ごみ箱への削除とファイルの追加は、対象外。
- **新規ファイルを作ったら、すぐ名前を付けられる**: フォルダを作ったときと同じ流れ(取り消すと、仮の名前のまま残る)。

## 触るときの注意

- `useFolderActions` は大きい(386 行)。400 行を超えそうなら、操作の種類ごとに、フックを分ける。
- 失敗の理由は、Rust が返す文字列に「exists」が含まれるかで見分けている(`renameItem`)。Rust のエラーの文言を変えるときは、ここも見る。
- 起動回数の記録(「よく使うもの」)は、パスで持っているので、名前を変えると数え直しになる。
