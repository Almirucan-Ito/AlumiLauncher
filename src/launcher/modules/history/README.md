# modules/history(元に戻す・やり直し)

`Ctrl+Z`(元に戻す)と `Ctrl+Y`(やり直し。`Ctrl+Shift+Z` も同じ)の履歴を持ちます(`useUndoHistory`)。

## 担当すること

- 元に戻す履歴とやり直しの履歴(どちらも最大 5 件。`MAX_HISTORY`)を持つ。
- フォルダ一覧と並び順の「写し」(`Snapshot`)を撮り、その内容に戻す(`snapshot` / `restoreSnapshot`)。
- 元に戻せる操作 1 つ(`HistoryAction` = 元に戻す処理 + やり直す処理)を積む(`pushHistory`)。新しい操作をしたら、やり直しの履歴は捨てる。
- ドラッグ中の並べ替えを、1 回の操作にまとめる(`reorderRecorded`: 最後の入れ替えから 1.2 秒で確定。`flushReorder` で、すぐ確定)。
- キー操作の受け付け(入力欄の中では、入力の取り消しを妨げないよう、何もしない)。

## 担当しないこと

- **何を履歴に積むかは、呼ぶ側が決める**(`modules/folders` の `useFolderActions`・`modules/home` の `useDragHandover` など)。ここは、入れ物と、戻す動きだけ。
- 画面の更新(`onRestored` で、呼ぶ側が一覧を取り直す)。
- 対象外の操作: 設定の変更、ファイルの追加、ごみ箱への削除(戻せない)。

## 対象になるもの

並べ替え・フォルダの作成/名前の変更/一覧から外す・アイコンの移動(実際のファイルの移動も戻す)・ファイルの名前の変更(実際の名前も戻す)。

## 設計の理由

- **写しは「フォルダ一覧 + 並び順」だけ**。設定の変更(色など)は、対象外にしている(コメントに、そう書いてある)。
- **ファイルを動かす操作は、`undo` / `redo` を関数で持つ**: 設定の写しを戻すだけでは、実際のファイルが戻らないため。
  戻す側が、もう一度 Rust を呼んで、ファイルを動かす。
- **戻している間は、次の「元に戻す・やり直し」を受け付けない**(`historyBusy`): ファイルの移動は非同期なので、重なって走らないようにする。
  失敗したら、その操作を履歴に戻して、失敗を知らせる。
- **プリセットを切り替えたら、履歴を捨てる**(`clearHistory`。`useSettingsActions` が呼ぶ)。
- **キーの購読は一度だけ**(`useLatest`): 中で、いつも最新の `runHistory` を呼ぶ。

## 触るときの注意

- 新しく「元に戻せる操作」を足すときは、変更の前に `snapshot()` を撮り、`pushHistory` に、`undo` と `redo` を渡す。
  ファイルを動かすなら、`undo` の中で、逆の操作を呼ぶ。
- 履歴の上限(5 件)を変える理由は、コードにも書かれていない。変えるときは、ここに理由を足す。
- テストは `useUndoHistory.test.tsx`。
