# modules/icons(アイコンの取得とキャッシュ)

ファイルのアイコン画像と、フォルダの中身の一覧を、Rust から取ってきて、覚えておきます(`IconController.ts`)。

## 担当すること

- アイコンを取得して覚える(`useIcon`)。覚えていれば、すぐ返す。
- フォルダの中身の一覧を取得して覚える(`fetchItems` / `cachedItems`)。フォルダを開くときに、待たせないため。
- 取得に失敗したものだけを取り直す(`retryMissingIcons`)。全部を捨てて取り直す(`resetIcons`)。
- 起動時、一覧とアイコンの取得が落ち着くまで待つ(`whenIconsSettled`)。

## 担当しないこと

- アイコン画像を取り出す処理そのもの(Rust の `platform/icon`)。
- アイコンを描く部品(`shared/ui/IconImg`。これが `useIcon` を使う)。

## 設計の理由

- **覚えておく数に上限がある**(`MAX_CACHED` = 160、最近使った順): 大量のアイコンを開いても、メモリが増え続けないため。
  `Map` は挿入順なので、使うたびに入れ直して「最近使った順」にしている。
- **同じアイコンを同時に何度も頼まない**(`pending`): 取得中なら、同じ約束(Promise)を返す。
- **失敗したら、仮のアイコンを出すだけで、覚えない**: 次に表示するとき・取り直したときに、もう一度取得する。
  起動直後は、取得に失敗しやすいので、起動の少しあとに `retryMissingIcons` で、失敗したものだけ取り直す(全部取り直すと、起動時の処理が倍になる)。
- **一覧の取得は、失敗したら 1 回だけやり直す**(300ms 後): フォルダを登録した直後は、設定の保存より先に、一覧の要求が届くことがあるため。
- **起動時に画面を出すのを、アイコンが揃うまで待たせる**(`whenIconsSettled`): アイコンが途中で入れ替わって見えないように。
  何も動いていない状態が続くか、最長の時間(呼ぶ側が決める。ホームは 3.5 秒)で、待つのをやめる。

## 触るときの注意

- 状態は、ファイルの中の `Map`(モジュールの変数)で持つ。画面の部品どうしで共有するためで、React の状態ではない。
  再読み込み(`App.tsx`)のときに、`resetIcons` で、すべて捨てて取り直す。
- 名前を変えた・移動したファイルは、パスが変わるので、新しいアイコンとして、また取得される。
