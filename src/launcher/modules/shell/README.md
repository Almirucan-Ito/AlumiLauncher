# modules/shell(アプリの外枠)

ウィンドウの外枠と、機能をつなぐ「要」です。どの機能にも属さない、アプリ全体の部品と常駐の処理を置きます。

## 担当すること

- **設定の持ち方**: `useConfigStore`(画面の状態と、Rust への保存をいっしょに扱う)。
- **外枠の部品**: `TitleBar`・`PresetSwitcher`・`CornerButtons`(右下の ＋・再読み込み・設定)・`ContextMenu`・`DeleteDialog`・`ConsentDialog`(外部通信の同意)・`Pickers`(ウィジェット・ミニアプリ・スタートメニューの追加画面をまとめて出す)。
- **常駐の処理**(画面に出ない): `useAppServices`(音量・ツールチップ・起動時の復元・Rust からの通知をまとめる)、`useAppEffects`(起動時の設定・背景画像・Windows のテーマカラーの読み込み、クリックでメニューを閉じる、フォルダが消えたら閉じる)、`useBackendEvents`(登録フォルダの変化・ミニアプリのフォルダの増減・設定の保存の失敗の通知を受ける)、`useStartupRestore`。
- **キー操作**: `useGlobalKeys`(Esc・再読み込み・プリセットの切り替えの、それぞれのフック)、`useAppKeys`(何を開いているかで、効くキーを切り替えて、それらをまとめる)。
- **ウィンドウの状態**: `useWindowMode`(小さい表示 `compact`・最大化)、`useToast`、`usePickers`、`usePlusButton`。
- **見た目の切り替え**: `AppLookModel`(`.app` のクラス名と、ホーム・フォルダ内の並べ方を決める)。

## 担当しないこと

- ホーム・フォルダ・ウィジェットなど、**各機能の中身の処理**(それぞれの `modules/*`)。ここは、つなぐだけ。
- 色や大きさの値(`settings/ThemeModel` と CSS)。

## 設計の理由

- **設定の変更は、必ず `mutate` を通す**: ダイアログを開いている間など、非同期の途中で設定が変わっても、古い内容で上書きしないよう、
  変更を、常に最新の設定(`configRef`)に対して適用する。直接 `config` を書き換えない。
- **起動時の復元は、一度だけ**: `useStartupRestore` は、設定が読めたときに 1 回だけ、音楽プレーヤーとアラームを元に戻す。
  アイコンの取り直しは、起動の少しあと(1.5 秒)に、失敗したものだけを行う(全部取り直すと起動時の処理が倍になるため)。
- **`appClassName` が、テーマ・UI の色・小さい表示などを、すべて `.app` のクラスにする**: CSS は、そのクラスだけを見て切り替える
  (JS から、スタイルを直接書かない。`shared/styles/README.md` を参照)。
- **`shell` は、ほかの機能への依存が多い**(`Pickers` などが、各機能の部品を並べるため)。これは「つなぐ役」なので許していて、
  逆に、ほかの機能から `shell` の中身を使うのは、`DeleteDialog`・`ConsentDialog` などの共通のダイアログだけにする。

## 触るときの注意

- 新しい「画面に出ない常駐の処理」は、`useAppServices` から呼ぶ(`App.tsx` には書かない)。
- 新しいキー操作は `useGlobalKeys` に足す。文字を入力中は、ショートカットに取られないようにする(その判定が、同じファイルにある)。
