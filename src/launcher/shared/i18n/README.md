# shared/i18n(画面の文言)

ランチャー本体の画面に出る文言(日本語・英語)です。全体の方針と、ウィジェット・ミニアプリ・Rust 側の扱いは `docs/i18n.md`。

## 担当すること

- 辞書: `messages.ja.ts`(日本語)と `messages.en.ts`(英語)。
- 取り出す関数 `t("キー", { 名前: 値 })`(`i18n.ts`)。文言の中の `{名前}` を、値に置き換える。
- 表示言語の決め方: Windows の表示言語(WebView2 が `navigator.language` に反映)が日本語なら日本語、それ以外は英語。

## 担当しないこと

- ウィジェット・ミニアプリの文言(それぞれのフォルダの `i18n.ts`。本体の辞書には足さない)。
- Rust 側の文言(トレイのメニュー・初期フォルダの名前)。
- 利用者向けの説明(README など)は、日本語だけ。

## 設計の理由

- **辞書は、TypeScript の中に置く**(外部の JSON などは使わない): キーの書き間違いと抜けを、ビルド前に検査できる。`t("存在しないキー")` は、`tsc` が止める。
- **キーの型は、`ja` のキーから作る**(`Key = keyof typeof ja`)。`en` が、`ja` のキーを全部持っているかも、型で検査される。
- **日本語を基本にして、英語を、同じ場所に並べて書く**。
- **用語を統一する**(`i18n.ts` の先頭に書いてある): 「ホーム」= 最初の画面 / 「フォルダ内」= フォルダを開いた画面 / 「表示数」= 1 ページに並べる数。
  一覧から取り除く操作は「外す」、「既定」は「デフォルト」、「大きさ」は「サイズ」、「パソコン」は「PC」にそろえてある(今の辞書の表記に合わせる)。

## 文言を足す・直す

1. `messages.ja.ts` と `messages.en.ts` の**両方**に、同じキーを足す(直す)。
2. 画面では `t("キー")` を使う。文字を直書きしない。
3. `npm run check` を通す。
