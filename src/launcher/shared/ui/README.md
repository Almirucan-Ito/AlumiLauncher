# shared/ui(機能をまたぐ画面の部品)

どの機能からも使う、画面の部品です。

## 担当すること

- **`Pager`**: アイコンを、ページごとのグリッドに並べる一覧(ホームとフォルダ内で使う)。スワイプ・ホイール・矢印キー・端の矢印・点でページを送り、
  アイコンの長押しでドラッグを始め、並べ替え・重ねてフォルダを作る・端へ寄せてページ送り、をする。
  - 計算は `PagerModel.ts`(並べ方 `PagerLayout`・ページ数・端でのページ送りの仕組み)。画面を使わない。
  - ポインタ操作(スワイプ・ホイール・長押しドラッグ)は `usePagerDrag`、アイコンが動くときの滑らかな動き(FLIP)は `usePagerFlip`、キー操作は `usePagerKeyboard`、矢印の絵は `PagerArrow`、引数の型は `PagerProps`。
- **`AppTile`**: アイコン 1 つ(押すと起動する。`.alumiapp` はミニアプリを開く)。**`IconImg`**: アイコン画像(`modules/icons` の取得とキャッシュを使う)。
- **`MenuModel`**: 右クリックメニューの型。
- **`flat`**: ウィジェット・ミニアプリの一覧に使う、フラットデザインのアイコン(色の四角に白い図形)。
- **`storageui`**: データ・キャッシュの大きさの表示と、消すボタン(誤操作を防ぐため、2 回押して実行)。

## 担当しないこと

- どのアイコンを並べるか、並べ替えたあとに何を保存するか(呼ぶ側の `modules/home`・`modules/folders` が決める。`Pager` は、コールバックを呼ぶだけ)。
- ドラッグ以外の、機能ごとの画面。

## 設計の理由

- **`Pager` は、並べるものの型 `T` を知らない**(`render` で 1 つの描き方を受け取る): ホームのフォルダ・アイコンと、フォルダ内のアイコンで、同じ部品を使うため。
- **表示中のページと、その前後だけを描画する**: アイコンが多くても、描画が重くならないため。
- **アイコンが別の位置へ動くときは、元の位置から滑らかに動かす**(FLIP アニメーション)。
- **計算を `PagerModel.ts` に分ける**: `vitest` で試せる(`PagerModel.test.ts`)。ドラッグそのものは、自動のテストが薄い。
- **マスの大きさの比率は、CSS と同じにする**: `PagerModel.ts` の `CELL_W`(1.45)・`CELL_H`(1.35)・`CELL_H_EXTRA`(32px)・`CELL_H_COMPACT`(1.1)は、
  `shared/styles/pager.css` の `.page` と `compact.css` の `.app.compact .page` と同じ値。**片方を変えたら、もう片方も変える**(今は、自動では確かめていない)。
- **端でページを送る待ち時間などの数値は、`shared/api/TuningModel.ts`**。

## 触るときの注意

- `Pager.tsx` は大きいので、新しい動きは、`usePager〜` のフックに分ける。
- アイコンの大きさは、CSS 側(`--icon-size` を上限に、ウィンドウに合わせて縮む)でも決まる。JS の計算(何個並ぶか)と、CSS の計算(1 つの大きさ)が、食い違わないようにする。
